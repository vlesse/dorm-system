# 宿舍管理系统 · 青山园区（IMIP）

印尼中苏拉威西 Morowali 青山工业园自建宿舍的企业级管理系统。一期目标是**让宿舍数据变准**：
床位级建模、时间区间入住记录、可配置的排宿规则、随时能交出去的在住花名册。

## 跑起来

```bash
npm run setup   # 安装依赖 + 建库 + 生成模拟数据（首次）
npm run dev     # 同时起后端 3101 和前端 5183
```

打开 http://localhost:5183

重新生成模拟数据：`npm run db:seed`（会先清空业务数据，配置字典也会重建）

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Node 24 + TypeScript + Fastify + Prisma | 端口 3101，可用 `API_PORT` 覆盖 |
| 数据库 | SQLite（开发） | 上生产改 `schema.prisma` 的 provider 为 `postgresql` 即可，schema 按 PG 兼容写法书写 |
| 前端 | React 18 + Vite + Ant Design 5 | 端口 5183，`/api` 代理到后端 |
| 语言 | 中文 / Bahasa Indonesia / English | 右上角切换，文案在 `web/src/i18n.ts` |

## 三条不能动的设计原则

1. **最小可分配单位是床位（Bed），不是房间。** 房间是容器，床位才是资源。上下铺各自独立。
2. **入住是带时间区间的记录（Occupancy），永不覆盖。** 一张床的历史就是这张表的多行。
   事故追溯、警方检查、劳工部检查都靠这个。调宿 = 关掉旧记录 + 新建新记录，两条都留着。
3. **所有业务口径都在配置表里，不写死在代码。** 国籍、部门、职级（含休假周期）、班次、
   承包商、房型、排宿规则强度，全部在「设置」页改，改完立即生效。

## 数据模型

```
Site 园区
 └ Building 楼栋 (8 栋，层数不等；默认国籍 / 性别策略)
    └ Floor 楼层 (国籍归属可单独覆盖 —— 支持「1、2 层印尼籍，3 层中方」)
       └ Room 房间 (房型 / 状态机 / 可再覆盖国籍性别)
          └ Bed 床位  ← 真正的可分配资源

Person 人员 ──< Occupancy 入住记录 (时间区间) >── Bed
                  status: RESERVED 待入住 / ACTIVE 在住 / HELD 休假保留 / ENDED 已退宿
OccupancyEvent 操作流水（分配 / 入住 / 调宿 / 退宿 / 保留 / 返岗）
Device 设备 —— 挂在 BUILDING / FLOOR / ROOM 上，为二期监控预留
```

空间策略**逐级继承**：房间 > 楼层 > 楼栋。留空表示跟随上级，上级也留空表示不限。

## 排宿规则引擎

`server/src/services/rules.ts`。每条规则三档：`OFF 关闭` / `SOFT 仅提醒` / `HARD 强制拦截`。

| 规则 | 默认 | 为什么 |
|---|---|---|
| 男女不同房 | HARD | 不解释 |
| 国籍符合区域归属 | **SOFT** | 确实存在混住，不能一刀切拦死 |
| 房型职级门槛 | HARD | 干部单间、专家公寓有门槛 |
| 同房同班次 | SOFT | 白班夜班混住是宿舍矛盾第一来源 |
| 同房同部门 | SOFT | 紧急集合、班车方便 |
| 自有与承包商不混住 | SOFT | 费用结算主体不同 |
| 不得超住 | HARD | |
| 房间须可用 | HARD | 维修 / 隔离 / 封锁的房间不能进人 |

分配接口的行为：硬约束不通过 → 400 拦下；软约束不通过 → 409 带提醒返回，
前端弹窗让宿管确认，确认后带 `force: true` 再提交。**硬约束 `force` 也越不过去。**

## 休假周期

挂在职级上（`PositionLevel.leaveCycleMonths`，支持小数），当前配置：

| 职级 | 周期 |
|---|---|
| 普通员工 | 6 个月 |
| 工程师 / 科长 | 5.5 个月 |
| 部长 / 经理 | 4.5 个月 |
| 总经理 | 3 个月 |

「设置 → 职级 / 休假周期」里随时改，改完立刻影响告警推算。
`isLeadership` 开关决定谁算「中层及以上」，进而决定能不能住干部房。

## 待办告警（一期就带上，因为这几条最要命）

1. **离职未退宿** —— 人走了床位没释放。这是所有宿管系统数据烂掉的头号原因，
   支持一键批量清退。模拟数据里故意埋了 18 条。
2. **休假即将到期** —— 按各自职级周期推算。
3. **已分配超期未入住** —— 分了床 3 天没来办入住。
4. **状态口径不一致** —— 员工状态和床位状态对不上，说明两边流程脱节。

## 监控接入（二期，架构已预留）

一期**不接码流**，但点位已经登记在 `Device` 表里（每层楼一个楼道摄像头，`isActive: false`）。

二期只做两件事：
1. 起一个独立的视频网关容器（[go2rtc](https://github.com/AlexxIT/go2rtc) 或 MediaMTX），
   把海康 / 大华的 RTSP 转成浏览器直接能播的 WebRTC；
2. 在「设置 → 设备点位」把 `streamPath` 填上、`isActive` 打开。

**主应用永远不碰视频码流**，只管两件事：这层楼有哪些摄像头、当前用户有没有权限看。
所以接监控不用动主库、不用改数据模型。

部署上要注意：系统应装在**园区内网服务器**（监控流不能出园区，园区外网也不稳），
外部访问走 VPN。

## 一期没做、二期要做的

- 费用与分摊（住宿费按人天、水电按在住人天分摊、承包商月结账单）—— 字段已留（`RoomType.dailyRate`）
- 物品与押金（床上用品、柜子、门禁卡的发放与清点赔偿）
- 报修工单
- 查寝点名、违规记录（私拉电线、大功率电器、留宿外人）
- 访客登记
- HR 系统对接（人员以 HR 为唯一来源，离职自动触发退宿工单）
- 门禁联动（入住即开权限，退宿即注销）
- 房门二维码，宿管扫码直达房间
- 角色权限（楼栋宿管只看自己楼）与审计日志展示
- 监控接入
